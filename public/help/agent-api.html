LiveStage Lights / Working prototype 0.1

The control surface for agents.

Everything the operator can program has a command. Agents edit structured show data; the engine owns real-time playback.

Connect an agent

Open ☰ → Connect an agent in StageLight. It shows the exact setup for Claude Code, Claude Desktop / Cursor, Codex or any MCP client — this Mac's Node path, the MCP server path and the engine address (LIGHTS_URL) — with copy buttons, plus a first message that teaches the agent how StageLight works. The MCP server is named stagelight; when an agent starts it, it says hello to the engine every 10 seconds, so the dialog and the top bar show Agent connected.

MCP

Run the engine first. Add the included .mcp.json entry to your MCP client. The file uses an absolute path to this project. The adapter uses stdio and supports tools/list, tools/call and the initialization handshake.

{
  "mcpServers": {
    "stagelight": {
      "command": "node",
      "args": ["/absolute/path/stagelight/mcp/server.mjs"],
      "env": {"LIGHTS_URL": "http://127.0.0.1:1460"}
    }
  }
}

Begin with lights_schema and lights_status. Read groups, fixture calibration, and existing points before designing motion. Tools return errors for unsupported fields, invalid ranges and unavailable live operations. No arbitrary JavaScript or raw DMX execution tool is exposed.

Arming reaches physical hardware. It requires explicit human authorization and the confirmation argument shown in the schema. Never arm just to inspect, draft or preview. A preview succeeds without transmitting any physical packet.

A cue recipe

{
  "cue": {
    "id": "arrival", "name": "Arrival", "duration": 30, "loop": false,
    "tracks": [
      {"group":"backlights", "effect":"mirror", "start":0, "duration":30,
       "fadeIn":2, "fadeOut":3,
       "params":{"color":"#ffb84a", "secondary":"#6356dc", "speed":0.6, "brightness":0.7}},
      {"group":"rogues", "effect":"sweep", "start":0, "duration":30,
       "fadeIn":2, "fadeOut":3,
       "params":{"color":"#ffb84a", "speed":0.4, "brightness":0.5,
                 "panAmplitude":0.025, "tiltAmplitude":0.015, "prism":1}}
    ]
  }
}

Save with lights_cue_save, then play with {"id":"arrival","requestId":"rehearsal-001"}. Reusing the request ID will not restart the cue. Request IDs are deduplicated only during the current engine process lifetime.

Available effects: static, chase, wave, mirror, rainbow, pulse, sweep, orbit and sparkle. Use schema for the complete parameter constraints. Named position parameters pointA/pointB use per-fixture captures; they must already exist. New patterns can be implemented as deterministic renderer functions and exposed through the shared catalogue.

Pages, cue lists and GO

A page is a scene. Its cue list holds entries that point at library cues: {id, cue, label?, fade, follow: "manual"|"auto", wait?}. fade is the crossfade into that entry in seconds; 0 is a hard cut. follow: "auto" fires the next entry once this one has run wait seconds (default: the cue duration). Outgoing cues keep running during a crossfade.

lights_page_save {page:{id:"garden",name:"Garden",color:"#7fc79a",cues:[]}}
lights_effect_apply {preset:"breathe",group:"backlights",color:"#3a7bff",page:"garden",fade:3}
lights_effect_apply {preset:"circle",group:"movers",page:"garden",fade:2}
lights_look_capture {id:"curtain",name:"Curtain call",page:"garden",fade:4}
lights_page_go {id:"garden",requestId:"go-1"}      // next entry, or {entry:"…"} to jump
lights_page_back {}
lights_override_release {fade:3}                    // manual changes fade back to the cue

Read progress from lights_status: runtime.stack (page, entry, index, next, auto-follow countdown), runtime.transition (crossfade progress) and runtime.release (override fade-back). Manual overrides stay on top across GO until released. lights_cue_play still plays a single library cue outside any page and clears overrides; it accepts an optional fade.

Preview before live

lights_preview_cue plays a cue on a separate preview playback that the visualizer can show while the real cue list keeps running; it is never sent to Art-Net and is allowed while armed. Pass {id}, {page, entry} (uses the entry fade from the live look) or {cue} for an unsaved definition. lights_preview_go_live sends a saved previewed cue live; lights_preview_stop clears it. Read runtime.preview / runtime.previewFrames.

Visualizer visibility

lights_visualizer_hide {groups:["house-lights"], hidden:true} stops drawing those fixtures in the 3D view, which keeps big rigs fast. hidden:false shows them again. You can also pass fixtures to hide or show single heads. lights_visualizer_status reads what is hidden. This is preview only: output, cues and look reports are unaffected, and the setting is saved in the show.

Blind programming

lights_blind_set {enabled:true} makes lights_fixture_set, lights_fixture_clear, lights_point_recall and lights_override_release edit a blind buffer that only appears in runtime.previewFrames. lights_look_capture records the blind look; lights_blind_apply {fade} fades the blind changes onto the live lights. Lamp commands stay physical.

Playback settings

lights_settings_set {clearFade, blindFade} sets how many seconds Clear and blind clear/apply take (0 = instant). Saved in the show; read show.playback from lights_status. Explicit fade arguments still win.

Patch sheet

lights_patch_report (read-only) returns every fixture with profile, channel footprint, Hog universe:address range, Art-Net route, status (output, ready, unrouted, unverified, disabled), groups and this frame's DMX bytes, plus per-universe usage, the network path and routing issues.

Custom effects library

Built-in presets ship with the app (custom:false in lights_schema presets). Save new ones into the show with lights_preset_save {preset:{id, name, icon, effect, params, description?, duration?, loop?}}: choose effect from schema.effects (any with a layer) and icon from schema.icons. They come back with custom:true, a category from the effect's layer, and work anywhere a preset is accepted — lights_fx_preview, lights_fx_apply, lights_effect_apply — and in the Effects tab. lights_preset_delete removes custom presets only.

Programmer effects and recording

lights_fx_preview {fixtures, preset|effect, params?} shows a layered effect in runtime.previewFrames only; lights_fx_apply {} promotes it live with the same phase (or pass fixtures + preset to go straight live); lights_fx_stop / lights_fx_cancel stop or discard. Layers come from schema.effects[effect].layer: position (moving heads; circles the current aim), intensity (scales the current level) or color. Read runtime.fx and runtime.fxPreview. lights_cue_record {id} merges overrides and programmer effects into an existing cue (look entries with over:true, effects as layer tracks on explicit fixtures); a new id with page/after/go saves a copy of the playing cue plus changes; mode:"replace" snapshots the whole look.

Effect presets

lights_schema returns presets: strobe, fade-in, fade-out, breathe, chase, alternate, twinkle, rainbow, color-tide, bloom, circle, figure8, sweep and ballyhoo. Movement presets need moving heads in the group. lights_effect_apply turns one into a cue (optionally on a page) and returns created.cue / created.entry. Presets are only starting points; compose any multi-track cue directly with lights_cue_save. Fade presets set hold: true so the end state stays.

Groups, positions and selection

lights_group_save (full ordered list), lights_group_edit {id, name?, add?, remove?} and lights_group_delete manage groups (an movers group of every patched moving head is created automatically). lights_point_save stores one named position for several heads; lights_point_recall {id, ids} recalls it for just the listed fixtures. lights_selection_group / lights_selection_set move the operator's selection.

LED wall preview

lights_ledwall_set {media, brightness?, fit?} chooses what the 3D preview shows on the LED wall: a built-in from lights_schema media, an imported item from status show.media, or "off". lights_media_import {path, name} copies a local png/jpg/webp/gif or mp4/webm/mov/m4v (absolute path, 500 MB max) into data/media; lights_media_delete removes it. The wall is preview-only: nothing is sent to Art-Net or a video server, and video playback pauses in the UI while output is armed.

HTTP and event stream

POST /api/media?name=…&file=clip.mp4 with the session token header uploads a raw media body (what the LED wall tray uses). GET /media/<file> serves imported media with byte ranges.

The server binds to 127.0.0.1:1460. Read GET /api/session for a local session token, then include it as X-Lights-Token for mutations. Host and Origin are restricted to this local service. Tokens are renewed each process start.

GET /api/state       # complete show + runtime
GET /api/schema      # exact command definitions
GET /api/show        # JSON export
GET /api/events      # server-sent events, runtime at 10 Hz
POST /api/command
X-Lights-Token: [session token]
Content-Type: application/json

{"command":"cue.play","args":{"id":"arrival","requestId":"scene-12-take-1"}}

Response: {"ok":true,"runtime":...}. Validation failures use HTTP 400 with an error. A caller should keep its execution ID when retrying a play. Local clients can program cues without a browser or MCP session.

Triggers from other apps (OSC)

Live-show control from other apps (LiveStage, a sound or camera app) is OSC over UDP to port 1461 under /stagelight/… (GO a page or cue, back, stop, clear, blackout, master, play, LED wall, named triggers), and StageLight sends cue announcements and look summaries (Kelvin, level, color) to targets. Operator setup: Triggers from other apps. Full reference: docs/SISTER-APPS.md. Agents configure it with lights_network_configure, lights_trigger_save, lights_target_save and entry send actions in lights_page_save; read it with lights_network_status.

Look Link (camera colour temperature)

Protocol stagelight.look/1 (docs/LOOK-LINK.md) reports per-zone Kelvin, Duv, level, colour and a white flag to camera or lighting apps. Define zones with lights_zone_save {zone:{id,name,role,groups?,fixtures?}} / lights_zone_delete; set a target's look:{zones,mode:cue|change|off,members,heartbeat} with lights_target_save; add {target,message:"preset",preset,fade?} entry sends to recall the other app's presets (list: lights_target_presets {id,refresh}). lights_look_report {target?,zones?,cue?|page+entry} returns exactly what would be sent without sending; lights_look_send {target} sends now. Delivery, reply summaries and /stagelight/feedback show in lights_network_status. Do not assign a face zone without the operator saying which fixtures light faces.

Legacy OSC addresses

Loopback UDP port 1461. Only strings, int32 and float32 are accepted. OSC has no arming endpoint. Explicit state commands avoid toggle ambiguity.

AddressArguments
/lights/pingNone → /lights/hello
/lights/cue/playstring cueId, string uniqueExecutionId
/lights/stopfloat fadeSeconds
/lights/blackoutint 0 or 1
/lights/masterfloat 0..1

Reply /lights/ack contains execution ID, command, and accepted/duplicate. Errors return /lights/error. Replies go to the sender’s source IP/port. Other computers are heard only in Show network mode and only from allowed IPs (☰ → Network & triggers).

Persistence and extension

Show data is local, versioned JSON with atomic save. Effects and cues are data, not downloaded code. Unknown fixture profiles cannot transmit. Changing the patch requires disarmed output. All live adapters call the same engine handlers and validation. Consult docs/ARCHITECTURE.md for timing, failure behavior and the development roadmap.
